# Compose Doctor web playground

A landing page, documentation and an interactive playground for Compose Doctor. The playground
runs the **real, unmodified `compose_doctor` Python package** in the visitor's browser, so every
finding it shows is genuine analyzer output. Nothing is sent to a server.

## How the analyzer runs in the browser

```
src/compose_doctor/**/*.py ──(bundled at build time)──┐
web/src/analyzer/bridge.py ───────────────────────────┤
                                                      ▼
page ── postMessage ──► Web Worker ── Pyodide (CPython 3.14 on WebAssembly)
                                      ├─ PyYAML 6.0.3 (pure-Python sources from the sdist)
                                      └─ compose_doctor → JSON, text and SARIF reports
```

- **Same code as the CLI.** `src/analyzer/sources.ts` imports the package straight from the
  repository's `src/` with `import.meta.glob`, so the playground can never drift from the CLI.
  `bridge.py` only wires it together the way `cli.py` does for standard input: `load_bytes`,
  `lint` with the default configuration, and the real report renderers.
- **Why Pyodide and not a server.** Compose Doctor is pure Python with one pure-Python dependency,
  so it runs unchanged in Pyodide. Netlify Functions run Node.js, Go or Rust, not Python, so a
  server-side analyzer would need a separate Python host. Running in the browser needs no backend,
  no secrets, and has no server to attack or overload, and the user's YAML stays on their machine.
- **Self-hosted runtime.** `scripts/prepare-runtime.mjs` copies the Pyodide core from
  `node_modules/pyodide` and downloads the PyYAML sdist from PyPI (pinned version and SHA-256) into
  `public/runtime/` (git-ignored). The site makes no third-party requests.
- **Untrusted input.** The YAML is parsed by Compose Doctor's safe loader (`yaml.compose` with
  `SafeLoader`, alias-bomb and depth limits); it is never executed. The worker has no DOM, cookie
  or storage access. Input is limited to 200 KiB, and an analysis that runs past 10 seconds is
  stopped by terminating the worker. The Content-Security-Policy in `public/_headers` allows only
  same-origin scripts plus `'wasm-unsafe-eval'` for WebAssembly.

The landing and docs pages read `src/generated/analyzer-snapshot.json` (the rule catalogue and one
sample result) so they load without the runtime. It is generated by running the analyzer, and a
test fails if it is stale:

```console
python web/scripts/export_snapshot.py   # from the repository root, with compose-doctor installed
```

## Development

Requires Node.js 20.19+ (22 recommended). Network access to PyPI is needed once, to fetch PyYAML.

```console
cd web
npm install
npm run dev          # http://localhost:5173
npm run check        # ESLint, TypeScript, unit tests
npm run build        # production build in dist/
npm run test:e2e     # end-to-end tests against dist/ in Chromium (run after build)
```

`npm test` includes tests that boot Pyodide in Node and check that the analyzer's output matches
the CLI's golden file (`tests/golden/insecure.json`), that every example produces the rules it
promises, and that the generated snapshot is current. The end-to-end script serves `dist/` with
the production headers and drives the real UI, including keyboard use, a phone viewport and a
check that no request leaves the origin.

| Path | Contents |
|---|---|
| `src/analyzer/` | Worker, client (limits, timeouts), Pyodide setup, `bridge.py` |
| `src/features/playground/` | Editor (CodeMirror 6), results, findings, raw reports |
| `src/pages/` | Landing, docs, examples, 404 |
| `src/examples/` | Example Compose files and what each one should produce |
| `scripts/` | Runtime preparation, snapshot export, local server, end-to-end tests |

## Deploying to Netlify

The repository root has a `netlify.toml`, so no settings need to be entered by hand:

1. In Netlify, choose **Add new site → Import an existing project** and pick this repository.
2. Netlify reads `netlify.toml`: base directory `web`, build command `npm run build`, publish
   directory `dist`, Node 22. Leave the fields as detected.
3. Deploy. No environment variables or functions are needed.

Or from a terminal with the Netlify CLI: `cd web && npm run build && npx netlify-cli deploy --prod --dir dist`.

After deploying, open `/playground` and confirm the badge shows `compose-doctor 0.1.0` and the
insecure example reports 27 findings.

## Limitations

- The first visit downloads about 6 MB of runtime (cached afterwards); starting it takes a few
  seconds.
- The playground lints one file with the default configuration. `.compose-doctor.yml`,
  `--ignore` and multiple files are CLI-only; inline suppression comments work.
- Findings are reported against the file name `compose.yaml`.
